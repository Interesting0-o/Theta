## 二、分组模式：四条证据线

### 2.1 结构原子与协议边界——所有实现的共识

Theta 的「block 不可拆」（`AIMessage(tool_calls)` + 全部兑现 ToolMessage）与业界完全一致，且各家都用**占位符替换**而非物理删除来维持配对：

| 实现 | 机制 | 对 Theta 的意义 |
|---|---|---|
| **Anthropic context editing** | `clear_tool_uses_20250919`：清旧 tool result，**替换为占位文本**，配对保留；`clear_tool_inputs=true` 时连调用参数一起清 | Phase 2 清 args 有官方先例；占位符语义 =「已移除，需要可重取」 |
| **OpenCode Prune** | 旧工具输出替换为 `[output truncated by compaction]`，**数据库原文保留**，只改模型所见视图 | 「可逆墓碑」：checkpoint 即真值，mask 只是视图——与 Theta 现状同构 |
| **Gemini CLI** | `findCompressSplitPoint`：切分点必须落在**不含 functionResponse 的纯用户消息**上，保证切完后历史不以悬空工具调用开头 | 摘要式压缩时的配对保护，Theta 若做 Segment（LLM digest）同样需要 |

### 2.2 语义边界优于固定窗口——学界三连，直接支持 plan step 边界

这是本调研对设计稿**最有力的支持证据**：「按语义阶段分组压缩」在 2025–2026 年的三项独立工作中均被验证优于「最近优先 / 均匀采样」。

| 工作 | 分组机制 | 关键数据 |
|---|---|---|
| **自我分割轨迹**（arXiv:2608.02302） | agent 自己声明语义阶段（假设 → 证据 → 裁决），按阶段记录压缩 | 转录本压到 **6.5%** 大小，仍保留 **99.97%** 关键编辑命令、**100%** 测试结果；优于近因尾部与均匀采样；token 开销仅 +9.8% |
| **CAT / SWE-Compressor**（arXiv:2512.22087） | 压缩插入点 = 上下文膨胀信号 + **结构边界信号（子任务完成、策略切换、里程碑）** + 纠错信号；上下文分固定段 / 长期记忆段 / 工作记忆段三区 | 32B 模型 SWE-Bench Verified **57.6%**；上下文稳定 ~35k token；500 步仍持续改善（ReAct 基线 60 步后退化） |
| **SelfCompact**（arXiv:2606.23525） | training-free：rubric 提示让模型自判 COMPRESS/CONTINUE，**只在逻辑子目标达成点**压缩；rubric 作为 user 消息追加以复用 KV cache | 避免在关键推导/活跃子任务中途丢弃部分结果；「逻辑停止点压缩」优于 reactive（到顶才压）与 fixed-interval |

**对 Theta 的推论**：plan step 是**零额外成本的语义边界**（agent 已经声明了它），与「自我分割轨迹」的 agent-declared boundary 同族。§8.6 把 plan step 置于硬边界之下、预算切批之上的优先级顺序，与学界证据方向一致。无 plan 回退（连续窗 + 预算）对应基线方案，合理。

### 2.3 预算切批与最小清理量——缓存经济学

- **Anthropic `clear_at_least`**：每次激活若清理量不足设定值则**不动**。官方文档明确：清 tool result 会使缓存前缀失效、产生 cache write 成本，所以「每次清理要清得值得」。这与 Theta 滞回（高水位触发、低水位停止）是同一笔账，且 Anthropic 把它做成了显式参数。
- **OpenCode `PRUNE_MINIMUM = 20_000`**：清理量 < 20k token 不执行，避免「微不足道的清理」。
- **Theta 对应物**：`min_batch_chars`（指针开销 < min < max < 低水位）+ 滞回。业界两个独立实现都把「最小有效清理量」做成一等参数，验证了 §8.6 参数关系的方向。

### 2.4 豁免清单与保留策略横向对照

| 实现 | 触发 | 保留 | 豁免（永不压） |
|---|---|---|---|
| Anthropic context editing | 默认 100k input tokens（也可按 tool_uses 数） | 默认最近 **3** 个 tool use/result 对 | `exclude_tools` 白名单 |
| Gemini CLI | 历史达窗口 **50%** | 最近 **3 轮**工具响应完整；其余折叠到 **2048 字节**；压缩保留最近 30% 历史 | **检索类工具**（read_file/grep/glob）豁免折叠 |
| OpenCode | Prune 每次响应后；Summarize 在 `已用 ≥ 上限 − min(20k, max_output)` | 最近 **2 轮**用户对话 + 最近 **40k** token 工具输出 | **skill 类工具**输出豁免 |
| Cline（插件示例） | 上限的 **75%** | 近期 **24k** token；首条用户消息 | Focus Chain 待办列表穿越压缩存活 |
| Claude Code（社区拆解） | ~窗口 **78%** | 最近 **8–10 轮**；压缩后**重读最近编辑的 5 个文件**（>5000 token 只回路径引用） | 系统提示/CLAUDE.md/plan/skill 正文压缩后重注入 |
| **Theta §8.6** | `compressible_chars` 超水位 | 最近 **K=8–10 个 block** | web 四件套 / ask_user / dispatch / state 回执 / 失败与被拒 |

**读法**：Theta 的保留量（K=8–10 block）比 Anthropic/OpenCode 保守、与 Claude Code 同量级；豁免清单的设计（web 不可重取、ask 是人的决定、state 回执有权威源）与 Gemini「检索豁免」、OpenCode「skill 豁免」是同一逻辑——**豁免的不是「重要的」，而是「压了就丢真值的」**。Theta 失败/被拒回执原文保留这一条比多数实现更细（多数只按新旧，不按成败），值得保留。

## 三、压缩策略光谱：从无损到有损的完整菜单

| 层级 | 手段 | 代表 | Theta 现状 |
|---|---|---|---|
| 0. 源头 | 有界输出（保首尾截断） | OpenAI shell `output cap`（保首尾 + 省略标记）；Theta terminal `_compress_output` 8k | 已落地 |
| 1. 去重 | 同资源重复读取指针化 | Theta `CompressNode._dedupe_reads` | 已落地 |
| 2. 确定性 mask | 旧结果 → 占位符/指针，原文在库 | Anthropic clear_tool_uses；OpenCode Prune；Theta 双层压缩 | 已落地，§8.6 升级为批级 |
| 3. 清 args | 连工具调用参数一起清 | Anthropic `clear_tool_inputs`（默认 false，可选开启） | **未做，Phase 2 核心** |
| 4. 结构化摘要 | 不调 LLM 的统计型摘要 | Cline Context summary（工具清单 + 触及文件 + 高亮预览）；Theta 折叠摘要行 | 已落地（摘要行） |
| 5. LLM 摘要 | 摘要替换旧历史 + 重注入锚点 | Claude Code /compact（五段式 + 重读 5 文件）；OpenCode Summarize（回放最后用户指令）；Anthropic `compact_20260112`（trigger + instructions + pauseAfterCompaction） | 未做（设计稿称 Segment） |
| 6. 模型原生压缩 | 加密 compaction item，模型训练时原生支持 | OpenAI `/responses/compact`（`type=compaction`，`encrypted_content`；Codex `auto_compact_limit` 自动触发） | 依赖 provider，DeepSeek 无此能力 |
| 7. 可检索历史 | 压缩后历史仍可全文检索回查 | Cursor Dynamic Context Discovery（A/B 测 **-46.9%** 总 token） | notes/read_note 是弱化版；`read_event_log` 补了「旧调用成没成功」 |

两个值得记住的元结论：

- **压缩本身是大请求**：Anthropic 官方提醒「压缩大上下文本身就是一个大请求」，阈值太低反而费钱。Theta 纯确定性路线（不调 LLM）在这点上有结构性成本优势。
- **过度压缩会被重试吃回去**：Cursor 压缩后「忘掉刚才的编辑」是官方确认的高优 bug；社区共识是激进压缩需真实流量评测。支持 Theta「宁可少折」的保守默认值。

## 四、对 §8.6 未决点的逐条回应

| # | 未决点 | 调研结论 | 建议 |
|---|---|---|---|
| 1 | 轮末是否压刚完成周期 | SelfCompact/CAT/自我分割轨迹一致支持「在逻辑完成点压缩」；刚完成周期有 `A_final` = 天然逻辑终点，且其全部 block 必已消费 | **压**。把刚完成周期纳入轮末折叠区（保留 `A_final` 原文作为结论载体），比留到下一轮更符合「逻辑停止点」证据；注意这与 prompt「工作基调 8」（结论靠最终答复跨轮留存）正好配合 |
| 2 | 完整块墓碑 vs content 改写 | Anthropic/OpenCode 均为占位符 + 原文保留；Theta checkpoint 已持久化原文 | Phase 1 维持 content 改写；Phase 2 做**整块墓碑时保留 checkpoint 原文语义**（mask 是视图不是销毁）。args 清理照 `clear_tool_inputs` 先例：**默认只清 content，写操作 args 单独开一类**（write_file/edit_file 的 content 参数是大头且可重取——磁盘文件即真值） |
| 3 | K / max_batch_chars / min_batch_chars 实测值 | 业界保留量 3（Anthropic）到 8–10 轮（Claude Code）；最小清理量 20k token（OpenCode）/ 可配（Anthropic） | K=8–10 可先用；`max_batch_chars` 6k–8k 有样本支撑（无上限时单批 31k–39k 会过冲）；`min_batch_chars` 建议按「指针开销 × 批内条数」动态下界而非固定值，再上 P2 实测校准 |
| 4 | 混合块 `in_progress` 归新/旧 step | CAT 把「策略切换」列为边界信号；`in_progress` = 新 step 开工声明 | **归新 step**（块整体归新 step，理由：块是原子，而 in_progress 是该块内最具前瞻性的信号）；写进设计稿消除歧义 |
| 5 | 软边界（关键词 + 词嵌入） | 语义边界有效，但三项工作都用「agent 自声明 / 结构信号」而非事后嵌入聚类；嵌入方案无人给出生产级收益证据 | **降级为可选实验**。plan step 已覆盖大部分场景；软边界只在无 plan 长周期里有增量价值，优先级低于 Phase 2（args）与评估接线 |
| 6 | 统一 `CycleBatchPlanner` | Anthropic 把 clear_tool_uses / clear_thinking / compact 收进同一个 `context_management.edits` 数组——统一规划、分策略执行是主流形态 | **统一**。`CompactNode._plan` 的块解析抽成共享 `_iter_atoms/_iter_blocks` 后，两节点只剩「区域 + 处置策略」差异，统一 planner 自然成立 |

## 五、下一步落地路线建议

**P0（§8.6 Phase 1，批级 mask）**
1. 抽共享 `_iter_atoms` / `_iter_blocks`（`CompactNode._plan` 已有块解析）。
2. `CompressNode` 逐条 mask → `_plan_batches`：硬边界 → plan step（`plan_epoch, step_id`）→ 8k 预算切批。
3. 可压判定改逐 `ToolMessage`（允许混合块/含失败块部分压缩——样本证明整块严格到不了低水位：34,261 vs 17,482）。
4. 批级时间线指针 + `…[同批已压缩]` 短戳；保留最近 K 个 block。
5. 触发改 `compressible_chars`；`min_batch_chars` 作 clear_at_least 等价物。
6. 轮末折叠区扩到刚完成周期（未决点 1 若采纳）。

**P1（Phase 2，args 成本 + 评估）**
- 写操作 args 清理（`write_file`/`edit_file` 的 content 参数 → 指针 + 长度 + 路径；磁盘即真值）；样本 args 33.5k 是 content-only 压完后的大头。
- 评估接线：利用 provider 返回的 usage（`llm_usage` 日志已有 cache_hit/cache_read 字段）回填「字符↔token」换算，替代本地分词器；Anthropic count_tokens 端点支持压缩后预览的做法可作参照。
- 前后缀稳定性回归测试：批级压缩后缓存命中率不应显著下降（滞回 + 批量触发是缓存友好的关键）。

**P2（远期）**
- Segment（LLM digest）只在「确定性 mask 后仍超窗口」时作为逃逸阀；参照 OpenCode 五段式 + 回放最后用户指令、Claude Code 重读最近 5 文件的「重注入锚点」设计——Theta 的 RUNTIME_STATE（计划/记忆/技能每轮重注入）已天然覆盖大半。
- 软边界实验（仅无 plan 长周期）；`segmentation_version` 边界冻结缓存。
- 不做模型原生压缩路径（当前 provider 无此能力），但把压缩点抽象留在 planner 里，未来换 provider 时可平移。
